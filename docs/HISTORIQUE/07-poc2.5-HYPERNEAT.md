# 07 — poc2.5 : HyperNEAT (encodage indirect) — une impasse honnête

> 2026-07-15 → 2026-07-16. Dernier point ouvert de la feuille de route recherche
> (#4). Au lieu que le génome décrive *directement* le réseau, il décrit un
> **CPPN** interrogé sur la géométrie du capteur pour produire les poids d'un
> substrat fixe. V1 → V4, toutes falsifiées ; chantier clos. Sources :
> `docs/DESIGN-hyperneat-mvp.md`, `docs/FALSIFIED-hyperneat.md`, `SYNTHESE.md §6`.

---

## Intention

Changer de **paradigme d'encodage**. Jusqu'ici le génome décrit directement le
réseau 49→2 (encodage *direct*). HyperNEAT (Stanley et al.) propose un encodage
*indirect* : le génome est un **CPPN** (Compositional Pattern-Producing Network)
qui prend en entrée **6 coordonnées géométriques** (position de deux nœuds dans
l'espace du capteur) et produit **1 poids**. On interroge le CPPN sur toute la
géométrie de l'anneau de 16 rayons pour peupler les poids d'un **substrat fixe**.

**Pari** : exploiter la **régularité géométrique** du capteur (les 16 rayons sont
un anneau symétrique) pour produire des poids structurés plutôt qu'aléatoires, et
généraliser à d'autres résolutions sans ré-évoluer.

**Découverte de conception clé** : `Genome` / `NeuralNetwork` sont déjà
**agnostiques** à ce qu'ils représentent — le CPPN s'évolue avec l'infrastructure
NEAT existante **sans aucune modification** (mutation/crossover/spéciation
inchangés). C'est un MVP dé-risqué (convenu avec Robin).

**Deux outils livrés en prérequis** :
- `tools/inspect_network.py` : boucle **0-tick** (steer_score + score de régularité
  géométrique vs témoin aléatoire + test de transfert de résolution).
- `tools/trace_lineage.py` : reconstruit la **vraie lignée** du champion
  (agent → parent → … → fondateur) sur un run pop-pleine (monkeypatch
  process-local, jamais dans `src/`).

## Ce qui a été fait + résultats, version par version

### V1 — substrat dense, `weight_scale=3.0` (falsifié, pire régression du projet)
Campagne 6 seeds/15k : moyenne **67 → 15 % (−52)** — **dépasse le nœud de biais
(−34)** comme pire régression. Les 6 seeds régressent, **2 s'effondrent
démographiquement** (190/400 et 43/400 — jamais vu avant).
**Root cause diagnostiquée empiriquement** (pas juste un score) : `steer_score`
**exactement 0,0 sur 74/100 CPPN fondateurs** aléatoires, contre 0/100 génomes
directs. Le CPPN à 0 nœud caché (purement linéaire, seulement 6 poids fortement
corrélés) **sature son propre `tanh` de sortie**, noyant le signal d'un rayon
isolé.

### V2 — `weight_scale → 0,5`, substrat resté dense (re-falsifié, mieux mais insuffisant)
Sweep founder-level (0 tick) affine le diagnostic **avant** de brûler une campagne :
la densité seule n'est pas la cause dominante (sparsification via
`hyperneat.connectivity` réduit sans éliminer) ; c'est **`weight_scale`** (fondateurs
dégénérés 106/150 à 3,0 → **0/150 dès ≤0,75**). Campagne 6 seeds/15k : **15 → 19 %
(+4)**, toujours −48 sous le défaut. **Plus aucun effondrement démographique** (les
6 seeds à pop 400 — la saturation fondatrice était réelle et est corrigée). Mais
`hidden` moyen reste quasi nul (0,05–0,17) : hypothèse d'**évolvabilité limitée**
d'un CPPN à 6 poids fortement couplés.

### V3 — bootstrap d'1 nœud caché CPPN à la genèse (meilleur résultat, re-falsifié)
`hyperneat.bootstrap_hidden_nodes` appelle `Genome.add_node` N fois sur le CPPN
fondateur — réutilise l'opérateur de split NEAT, aucune machinerie nouvelle.
Campagne 6 seeds/**30k** (défaut relancé frais à 30k pour comparaison directe) :
**79 → 68 % (−11)**, écart réduit d'un facteur **~4-5** vs V2 (−48) et V1 (−52). Le
CPPN complexifie enfin (`hidden` moyen 0,05–0,17 → **0,87–1,40**), et **2/6 seeds
dépassent le défaut pour la 1ʳᵉ fois du chantier** (1 : 68 → 92, +24 ; 99 : 56 →
91, +35). Mais 2 régressent lourdement, dont un effondrement (5 : 96 → 50 ; **123 :
82 → 12**, `steer_median` à 0,000). Falsifié au sens strict (pas de 6/6 stable),
mais **progrès net et diagnostiqué**.

### V4 — 2 nœuds bootstrappés (relation NON monotone, chantier clos)
Test du « et si on pousse ? ». Moyenne **68 → 39 % (−29)** — contredit l'hypothèse
« plus de nœuds = mieux ». Le bootstrap fonctionne mécaniquement (`hidden` 2,03–
2,73) mais la **compétence ne suit pas** : les 2 seeds qui battaient le défaut en
V3 s'effondrent (1 : 92 → 32 ; 99 : 91 → 14), 42 chute aussi (97 → 28),
`steer_median` repasse négatif sur 4/6 seeds. **N=1 est un point de fonctionnement,
pas un curseur.**
**Diagnostic** : doubler la profondeur du CPPN sans ajuster le régime de mutation
qui doit l'exploiter dégrade — **même dynamique** que le génome sparse (poc2.3
volet 6) et le nœud de biais (poc2.4) : ajouter de la complexité fondatrice sans
adapter le régime évolutif qui doit l'exploiter casse la robustesse.

## Verdict

**Chantier CLOS** sur le constat de non-monotonie V3→V4. `hyperneat.enabled` reste
absent (=false) dans `default.yaml`. Mécanisme + outils gardés câblés/testés comme
référence (278 tests, pylint 9.99/10).

**Point notable pour la traçabilité** : c'est le **seul chantier du projet dont les
4 campagnes sont intégralement traçables** (logs archivés, 6 seeds × 30k chacune,
vérifié le 2026-07-22). Ironie utile : le chantier le mieux tracé est aussi une
impasse — ce qui rappelle que la traçabilité et le succès sont deux axes
indépendants (cf. `11`).

**Piste non explorée (limite assumée)** : **HyperNEAT V5** = un régime de mutation
CPPN dédié (ajusté pour un génome à 6-14 poids fortement couplés). Bien scopée,
coût connu — mais **non tentée**, le chantier ayant été déclaré clos sur la
non-monotonie qui rend le levier imprévisible avant affinage (voir `10`).

**Feuille de route recherche : 5/5 items traités** (n°1 fitness sharing, n°2
troncature, n°3 novelty, n°4 HyperNEAT, n°5 biais + îles). Tous falsifiés **sauf
novelty**, seul levier positif de la liste.
